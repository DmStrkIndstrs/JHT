# 정훈T 과학

학부모가 학생 코드로 학습 기록을 조회하고 선생님이 반·기간별 기록을 관리하는 사이트입니다.

- `index.html`: 중등, Firestore `jht/data`
- `go1.html`: 고1, Firestore `jht_h1/data`
- `jht-core.js`: 동시 수정 병합, 날짜, 일괄 입력 및 백업 검증 공통 함수

HTML 두 파일과 `jht-core.js`를 같은 경로에 함께 배포해야 합니다. 별도 빌드는 없습니다.

## 저장 및 사용 방식

수정 후 상단에 **저장됨**이 표시될 때까지 기다립니다. 네트워크 오류는 **다시 저장**으로 재시도할 수 있습니다. 다른 기기가 같은 항목을 수정하면 덮어쓰지 않고 중단합니다. **입력 백업 후 최신 내용 불러오기**로 미저장 데이터를 내려받고 서버 데이터를 확인한 후 필요한 변경을 다시 적용합니다. 브라우저를 강제 종료하거나 기기 전원이 꺼지는 상황까지 입력 복구를 보장하지는 않습니다.

서로 다른 학생·피드백·필드의 동시 수정은 트랜잭션에서 병합합니다. 현재 저장 형식은 기존 단일 문서를 유지합니다. 문자열 배열인 공지는 같은 배열을 동시에 수정하면 충돌로 처리됩니다. 데이터 규모가 커지면 학생별 문서로 분리해야 합니다.

종합 기록은 자동 저장되고, 개별 기록은 **추가하기/수정 저장**을 눌러야 합니다. 작성 중 이동하면 확인창이 나타납니다. 일괄 붙여넣기는 `학생 코드 또는 이름[탭]내용` 형식이며 동명이인은 코드로 지정합니다. 오류가 있는 행은 먼저 수정해야 전체 적용할 수 있습니다. 쉼표 구분은 첫 쉼표만 구분자로 사용하며, 여러 줄 셀이나 완전한 CSV 가져오기는 지원하지 않습니다.

과거 데이터의 출석률·과제 수행률은 당시의 현재 기간으로 한 번 옮겨집니다. 과거 기간 수치는 추정하지 않고 **미기록**으로 표시합니다. 학생 관리에서 기간을 선택해 입력합니다. 기존 `8/20` 일정은 그대로 표시되며 날짜 선택 시 연도를 포함한 형식으로 바뀝니다.

복원 파일은 구조와 코드 중복을 검사하고, 적용 전에 현재 데이터를 백업합니다. 저장 완료는 상단 상태로 확인합니다.

## 아직 필요한 Firebase 접근 권한 개선

**이 변경은 학생별 접근 제어를 완성하지 않습니다.** 현재 페이지는 전체 문서를 읽고 브라우저에서 학생 코드와 관리자 비밀번호를 비교합니다. 6자리 코드와 중복 검사는 사용 오류를 줄이는 기능이며 보안 인증을 대체하지 않습니다. 실제 배포된 Firestore 규칙은 이번 작업에서 조회하거나 변경하지 않았습니다.

실제 학생 정보 보호를 위해 별도 작업이 필요합니다.

1. Firebase Authentication에서 선생님 계정을 만들고 관리자 권한을 부여합니다.
2. 관리자 비밀번호를 공개 데이터에서 제거하고 Firebase 로그인으로 전환합니다.
3. 학생별 공개용 문서를 분리하고, 인증된 보호자와 자녀를 연결하거나 서버에서 제한된 조회 토큰을 검증합니다. 코드 원문이나 전체 학생 명단은 공개하지 않습니다.
4. Firestore 규칙에 학생별 읽기 권한과 선생님 쓰기 권한을 적용하고, 에뮬레이터에서 타 학생 열람·비인증 쓰기 거부를 확인한 뒤 데이터를 이전합니다.

인증 코드와 데이터 이전 없이 규칙만 잠그면 현재 사이트가 중단되므로, 이 전환은 함께 배포해야 합니다. 기존 공개 문서/이전 버전의 접근도 함께 차단해야 합니다.

## 테스트

Node.js에서 `npm install`, `npx playwright install chromium`, `npm test`를 실행합니다. 기존 Chrome을 사용할 때는 `JHT_BROWSER_PATH`에 실행 파일 경로를 지정합니다.

테스트는 실제 Firebase에 연결하지 않고 샘플 데이터와 모의 저장소를 사용합니다. 두 HTML의 JSX 문법, 학부모·관리자 흐름, 이동 시 입력 보호, 일괄 입력, 코드 중복, 검색, 기간별 수치, 날짜, 저장 재시도, 동시 수정 병합과 충돌을 확인합니다. 실제 Firebase 규칙, 네트워크 지연 및 PDF 출력 레이아웃은 별도 운영 검증 대상입니다.
